# Priority 1 — Fix reflection and memory correctness

`reflection.py` currently appears to use an older reflection prompt that does not strongly separate:

* statements made by the owner;
* statements generated by Lilith;
* interpretations;
* self-beliefs.

Fix this first.

Reflection must receive clearly separated blocks:

```text
CURRENT SELF STATE

OWNER MESSAGE

LILITH RESPONSE
```

Rules:

* facts about the owner may only come from the owner's message or other trusted evidence;
* never attribute something Lilith said to the owner;
* Lilith's metaphors must not become factual memories;
* generated stage directions must not become observations;
* self-beliefs should describe observed patterns in Lilith's behavior;
* affect variables are computational state;
* if nothing important happened, reflection may return no updates.

Use Ollama structured-output schemas rather than relying only on prose JSON instructions.

Add regression tests specifically proving that provenance cannot drift.

Example:

Owner:

```text
I like robotics.
```

Lilith:

```text
Maybe we should make a game together.
```

Valid memory:

```text
The owner is interested in robotics.
```

Invalid memory:

```text
The owner proposed making a game.
```

Also make `save_message()` return the inserted message ID and attach source message IDs to reflection work so durable memories can eventually be traced back to evidence.

# Priority 2 — Introduce real database migrations

The schema is currently distributed across multiple modules using `CREATE TABLE IF NOT EXISTS`.

This will become unmaintainable as Lilith develops.

Create a versioned migration system.

Add:

```sql
schema_migrations
```

with:

```text
version
name
applied_at
```

Every migration must:

* run once;
* run in a transaction;
* rollback completely on failure;
* preserve existing v0.1.0 user data;
* never require database deletion.

Every SQLite connection must explicitly configure:

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 30000;
```

Add migration tests.

# Priority 4 — Fix model concurrency

Lilith currently has multiple worker processes capable of calling the same Ollama server:

* conversation;
* routing;
* reflection;
* executive cognition;
* research;
* workshop;
* curiosity.

This means background cognition can compete with direct conversation.

Add model-request arbitration.

Owner conversation must have highest priority.

Suggested priority:

```text
conversation       100
router              95
owner executive     80
owner research      75
owner workshop      70
reflection          40
background work     30
curiosity           10
maintenance          5
```

Only model inference needs arbitration.

Do NOT serialize ordinary filesystem, Git, HTTP, testing, or tool work.

Requirements:

* background inference waits when owner conversation is queued;
* stale model leases recover after crashes;
* cancellation releases leases;
* leases are audited;
* curiosity never begins inference ahead of an owner request.

# Priority 7 — Fix curiosity reinforcement

Currently the curiosity worker appears to strengthen an interest merely because the topic was selected.

That creates a feedback loop:

```text
high interest
→ selected more often
→ selection increases interest
→ selected even more
```

Do not increase fascination simply because a topic was chosen.

Instead:

```text
select topic
→ research it
→ reflect on actual outcome
→ optionally adjust interest
```

Interest changes should come from meaningful engagement/results.

Also reduce repetitive curiosity by penalizing topics explored very recently.
